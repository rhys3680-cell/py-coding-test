# 2주 스프린트 — 코딩테스트 실전 대비

**시작**: 2026-07-31 / **목표 시점**: 2026-08-14 (2주 이내 임박)

## 왜 트랙을 바꿨나

기존 [algo_thinking](../algo_thinking/) 트랙은 **사고 전환**이 목표였고, 실제로 성공했다
(invariant 사고 정착 = 2026-06-02 "유지" 판정).

문제는 **속도**였다:

- 4월 ~ 7월 (3개월) 동안 Phase 1 문제 4개를 못 넘김
- 원인: 문제 1개당 산출물이 무거움 (5단계 양식 + 자가점검 + 판정표 + 로그)
- → 세션 진입 비용 ↑ → 미룸 → 공백 → 망각 측정 필요 → 망각 측정이 또 세션 소모
- **메타 작업이 실제 문제풀이를 밀어냈다**

2주 남은 시점에서는 이 구조를 유지할 수 없다.

## 라이브러리 제약 없음 (2026-07-31 변경)

Day 1은 `sorted`/`set` 금지 같은 제약을 걸었다. 이건 algo_thinking 트랙(사고 훈련)의
장치를 그대로 가져온 것인데, **스프린트 목표와 맞지 않아 폐기**한다.

- 실전 코테에서 표준 라이브러리를 잘 쓰는 건 감점이 아니라 **가점**이다
- 제약이 오히려 난이도를 실전보다 높였다 (Day 1 문제 A: 3줄로 끝날 걸 30분 소모)

**기본**: 라이브러리 마음껏. 실전과 동일하게, 빠르게.
**예외**: 그 자료구조 자체가 문제의 핵심일 때만 (스택 문제는 오히려 `deque`를 **써야** 함).
