## 핵심 목표

문제를 받으면 본능적으로 자문하기:

## 사고 전환 5단계 v2 (Invariant 중심)

> v1 양식의 약점 발견 (s1 풀이 후 진단): [2]가 코드 구조 묘사로 전락, [3] 상태 변수에 문제 조건이 누락됨. 양식이 사고를 끌어주지 못함. → **Loop Invariant 중심으로 재설계**.

자세한 배경은 [loop_invariants.md](loop_invariants.md) 참조.

각 드릴 문제마다 5단계를 채워서 풀이:

```
[1] 문제 읽기

[2] 손풀이 (작은 입력 1개로 표 그리기):
    | i | 본 값 | 변수1 | 변수2 | ... |
    종료 → 답: ?

[3] Invariant (한 문장):
    "i번째 원소까지 본 시점에, [변수들]은 [관계]를 만족한다"
    
    체크: 문제의 모든 요구사항이 명제에 들어갔나?
    (예: "최대", "중복 한 번", "처음 만난" 같은 키워드 명시 필수)

[4] 3-부분 점검:
    (a) 초기화: 시작 시 명제 참?
    (b) 유지: 한 번 돌고도 명제 참?
    (c) 종료: 끝났을 때 명제가 답을 알려주는가?

[5] 파이썬 코드:
    (a) → 변수 초기화
    (b) → 루프 본문
    (c) → return
```

**핵심 원칙**:
- **[3] Invariant가 핵심**: "변수가 무엇인가"가 아니라 **"변수들 사이 관계가 무엇인가"**
- **문제 조건의 모든 키워드가 [3]에 반영**되어야 함 ("최대", "중복", "처음" 등)
- **[5] 코드를 머릿속에 그리지 말고** [2]→[3]→[4] 순서대로 작성
- [4]에서 (a)(b)(c) 점검이 통과되면 [5]는 거의 자동 도출
